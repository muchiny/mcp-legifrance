## Global Constraints

- Rust edition 2024, `rust-version = "1.88"` (`cargo +1.88 check --workspace --all-targets --locked`), toolchain `1.99.0`.
- Crates préfixés `lf-` ; identifiants Rust en anglais et ASCII ; docs et commentaires en français ; messages d'erreur en anglais, sans point final. Dans la prose française, un nom CamelCase ou de produit prend des backticks (`clippy::doc_markdown`).
- Dépendances : exigence au niveau mineur dans `[workspace.dependencies]`, `default-features = false` au niveau du workspace quand c'est voulu ; une dépendance n'est déclarée dans un manifeste que lorsqu'un code l'emploie (`cargo machete`). R6 : `chrono-tz` n'est déclarable normalement que dans `lf-adapter-piste` (et `lf-app`) ; R8 : les dev-dependencies sont contrôlées.
- **Âge minimal** : toute version ajoutée dans `Cargo.lock`, transitive comprise, est publiée depuis au moins 14 jours (`make min-age`, procédure : index sparse de crates.io, `cargo update -p <paquet> --precise <version>`, une exigence `"1.53"` laisse cargo prendre 1.54 ; `cargo update -p … --precise` ne marche qu'après la résolution : lancer d'abord `cargo metadata --format-version 1 > /dev/null`, la commande unique de ce plan pour cette résolution). **Aucune exception `security-fix` n'est prévue dans ce plan** : les versions de l'essai (serde_path_to_error 0.1.20, chrono-tz 0.10.4, phf 0.12.1, phf_shared 0.12.1, siphasher 1.0.4) ont toutes plus de 14 jours au 2026-10-22.
- Lints : `clippy::pedantic`, `unwrap_used`, `expect_used`, `panic`, `unreachable`, `unimplemented`, `todo`, `dbg_macro` bloquants par `-D warnings` ; `unwrap`/`expect` permis dans les tests seulement ; `unsafe_code = forbid` (pas de `std::env::set_var`). Aucun `#[allow]` ni `#[expect]` sans `reason`. **Un seul** `#![cfg_attr(not(test), expect(dead_code, reason = …))]` de crate, déjà posé dans `lib.rs` ; aucune tâche n'en ajoute un autre, seule sa `reason` est ajustée ; il part au plan 2e. Piège : cet attribut est inactif sous `cfg(test)` — un champ, une variante ou une fonction jamais employé(e) par les tests fait échouer `clippy --all-targets` : ne déclarer que ce qu'un test lit.
- Ports : pas de `async_trait`, pas de `dyn` sur un port, aucune méthode par défaut (ADR-0012).
- `--locked` sur toute commande cargo (seule exception : la résolution initiale `cargo metadata --format-version 1 > /dev/null`, qui crée l'entrée d'une nouvelle dépendance, tâches 4 et 8). Le job `test` de la CI exécute les tests avec `HTTPS_PROXY=http://127.0.0.1:9 HTTP_PROXY=http://127.0.0.1:9 NO_PROXY=127.0.0.1,localhost,::1 CARGO_NET_OFFLINE=true` : toute la suite doit passer ainsi.
- Qualité (00 §10) : TDD ; `make cov` = 100 % des lignes, régions et fonctions (`--lib`) ; `make mutants FILE=<fichier>` = 0 `MISSED` et 0 `TIMEOUT` sur chaque fichier de **production** dont une fonction change, un fichier à la fois (`WARN No mutants found` vaut succès : c'est le cas des structs à dérivation seule ; exception assumée : un fichier dont seul le `mod tests` change, comme `retry.rs`, n'est pas muté). Aucune décision dans une fonction `new` ni dans un `impl Default` (cargo-mutants ne les mute jamais) : la logique va dans un helper. Toute boucle garantit sa progression même mutée. Dans les tests : ni `assert!(matches!(…))`, ni `let … else { panic!() }`. Piège de couverture : `cargo llvm-cov` résume une fonction générique par son instance la plus couverte.
- Tests de l'adapter : wiremock, **pas** d'horloge tokio gelée pendant des E/S réelles ; `ManualClock` + `RecordingSleeper` rendent le temps déterministe. Un port « fermé » s'obtient par un `TcpSocket` lié et non écouté (tâche 3), jamais par « bind puis drop ».
- **Aucune valeur du corps de réponse dans un message de `Decode`, un `Debug`, un `Display` ni un journal** (données personnelles possibles, texte juridique long) ; seuls figurent le chemin JSON masqué et la catégorie serde (tâche 4). **Seule exception** : le message d'erreur PISTE d'un 400 (consultation ou `/search`, jamais l'endpoint du jeton), nettoyé, borné à 200 caractères et privé des secrets exacts, qui devient le `detail` de `InvalidRequest` (tâche 5 ; 04 §5.1, §11.2 règle 3) ; il n'est journalisé que pour une consultation, jamais pour `/search`, où il peut citer le texte de la requête (04 §12.5). Un DTO qui peut porter un texte de corps ne dérive `Debug` (et `PartialEq`) que sous `cfg(test)` (exceptions assumées : `RawDate`, qui dérive `Debug` en permanence, et `OAuthErrorDto` du plan 2c ; un type qui les contient ne se journalise pas en `{:?}`).
- WSL (`~/.claude/rules/wsl-safety.md`) : jamais `cargo test -j 4` ni plus ; `cargo mutants` uniquement par `make mutants` (un fichier, `-j 1`).
- Commits : un par tâche, message en français au format conventionnel, sans trailer ajouté par l'implémenteur (le contrôleur ajoute le trailer `Co-Authored-By`). Rien n'est poussé avant la fin.

## Review Focus

1. **Valeurs du corps dans les messages** : un champ de type inattendu (`integer 12` au lieu d'une chaîne), une clé inconnue contenant un secret, un détail d'erreur PISTE qui recopie l'en-tête `Authorization` — le message nomme le genre et le chemin, jamais la valeur. Tests : tâche 4 (`decode`, test de non-fuite), tâche 5 (secrets retirés du détail, y compris un jeton coupé par un caractère invisible : `a_token_split_by_a_zero_width_space_is_still_redacted`, ROUGE si l'on expurge avant de nettoyer).
2. **Réponse hostile ou bizarre** : JSON imbriqué à 63 et 64 niveaux de sections (127 et 129 de profondeur) et à 200 niveaux, `[]`, `null`, texte HTML ou JSON tronqué à la racine, `facets` énorme, `data` d'ACCO de 1 Mio — `Decode` ou ignoré, sans panique ni allocation sans borne. Tests : tâches 4, 6, 7.
3. **Dates** : `singleDate` aux changements d'heure de Paris, aux bornes 1500-01-01 et 2221-12-31, avant 1911 (temps moyen) ; fond sans facette de date ; page × taille au-delà de 10 000 ; `version_date` manquante sur LODA/CODE — vecteurs exacts, jamais d'appel réseau pour une requête que la garde refuse (au niveau de `search_body`, qui n'a pas de réseau ; le wiremock `expect(0)` est au plan 2e). 4. **« Introuvable »** : jamais `NotFound` sur `/search`, sur l'endpoint de jeton ni sur un 500 ; un 404 de passerelle (HTML) ou d'un hôte non officiel est `Config` ; le 400 « valider est fausse » d'une consultation est `NotFound`. Tests : tâche 5.

Tests : tâches 5, 8 et 9.
