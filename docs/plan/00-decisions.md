## 3. Ports (`lf-application::ports`)
- Style : traits en async natif façon RPITIT, `fn get_decision(&self, id: &DecisionId) -> impl Future<Output = Result<Decision, CorpusError>> + Send;` implémentés avec `async fn` ; génériques (dispatch statique) ; sélection PISTE/DILA à l'exécution par un `enum AnyCorpus` (M9). Pas de `async_trait`/`dyn` sauf justification (ADR-0012).
- `LegalCorpus` (sortant, unique) : `search(&SearchQuery) -> SearchPage` ; `get_act(&LegiTextId, VersionDate) -> Act` ; `get_article(&ArticleId) -> ArticleText` ; `get_decision(&DecisionId) -> Decision` ; `get_deliberation(&CnilTextId) -> Deliberation` ; `get_convention(&KaliTextId) -> Convention` ; `get_company_agreement(&AccoTextId) -> CompanyAgreement`. Ajouts : M6 `find_article(&CodeRef, &ArticleNum, VersionDate)`, `find_by_number(...)` pour la résolution, `list_codes()` (codes abrogés compris, avec leur `etat` ; chargée paresseusement au premier besoin, jamais au démarrage ; l'adapter garde une seule table, TTL 7 j, qui sert aussi `find_article` et les completions de M7) ; M7 `article_versions(&ArticleId) -> Vec<ArticleVersion>`, `related_links(&ArticleId)`. Pas de méthode `suggest` (`/suggest` retiré, §8).
- `AuditLog` (sortant) : `record(&AuditRecord) -> Result<(), AuditError>`.
- `Clock` (sortant) : `now_utc()`, `today_paris() -> CivilDate` (date civile Europe/Paris, calculée par `chrono-tz` dans `lf-app::clock` ; décision C3).
- Entrant : pas de trait ; cas d'usage `…UseCase` avec `async fn execute(&self, input) -> Result<Output, AppError>`, regroupés dans `LegalService<C: LegalCorpus, A: AuditLog, K: Clock>` injecté dans l'adapter MCP. `Audited` enveloppe CHAQUE exécution : succès, `invalid_arg` (y compris les échecs de décodage des arguments, §5), `not_found`, erreurs amont — tout est journalisé avec une durée réelle (corrige D-02 et D-03).
- Délai global : `Audited` mesure la durée (`tokio::time::Instant`), exécute le cas d'usage sous `tokio::time::timeout(LF_TOOL_DEADLINE_S)` (seule garde dure) et publie l'échéance dans `lf_application::deadline::Deadline`, variable locale de tâche (`tokio::task_local!`, feature `rt` de tokio, §2). Les adapters la lisent (`Deadline::current_or(défaut)`) comme une durée restante (`Duration`), convertie dans leur propre horloge monotone à l'entrée de la méthode du port (les horloges de test des adapters restent cohérentes), et ne programment aucune tentative ni attente qui la dépasserait : ils rendent tout de suite une erreur explicite (`RateLimited { retry_after }`, `Timeout` ou dernière erreur). Les cas d'usage n'utilisent pas `tokio::spawn` (sinon, propagation explicite) ; ceux à appels multiples cessent d'en lancer à 80 % du délai et rendent un résultat partiel motivé. Dépassement → `upstream_error` (`UpstreamCause::Deadline`).

## 5. Erreurs
- `CorpusError` (précisée au plan 3a, `ports/corpus.rs` ; AM-44) : `NotFound { what }` (`what` = gabarit de l'endpoint qui n'a rien rendu, `/consult/juri`, jamais l'identifiant demandé), `InvalidRequest { status: Option<u16>, detail }`, `Upstream { status: Option<u16>, retryable, detail }` (`status: None` = erreur réseau ; `retryable` ne sert qu'au message, §8), `Timeout`, `RateLimited { retry_after: Option<Duration> }`, `Auth { origin: AuthOrigin, status: Option<u16>, detail }` (`AuthOrigin::Token` : endpoint du jeton, 400, 401 ou 403 ; `AuthOrigin::Api` : second 401 de l'API, ou 403 de l'API dont le corps n'est pas une page HTML), `Config { kind: ConfigKind, detail }` (`ConfigKind` : `CredentialsMissing`, `OAuthResponse`, `ApiEndpoint`, `OAuthEndpoint`, `Settings`), `Decode { detail }`, `TooLarge { detail }` (corps de `/search` ou d'une consultation au-delà de la borne de corps, jamais réessayé ; le corps trop gros de l'endpoint du jeton reste un `Decode`). Le message du modèle se rédige à partir des seuls champs typés (variante, statut, `AuthOrigin`, `ConfigKind`), jamais en analysant un `detail`.
- `AppError` : `InvalidArgument`, `NotFound`, `Upstream` (détaillé par `UpstreamCause` : `Status(u16)`, `Network`, `Timeout`, `Deadline`, `Decode`, `Cancelled`, pour les journaux et l'audit, sans nouveau code MCP), `RateLimited`, `Config`, `Audit`.
- MCP (ADR-0010) : erreurs métier → résultat `isError: true`, texte seul `[code] message actionnable` avec codes `invalid_arg`, `not_found`, `upstream_error`, `rate_limited`, `config_error`, `audit_error` ; erreurs de protocole → JSON-RPC (liste fermée au point suivant). Une erreur OAuth (400/401/404 sur l'endpoint token) → `config_error`, jamais `not_found` (corrige D-10). Jamais de secret, de token ni d'URL avec paramètres sensibles dans un message ou un log.
- Arguments d'outil : reçus en `JsonObject` avec un `input_schema` explicite (`schema_for_input::<P>()`), décodés par `lf-adapter-mcp` (`serde_path_to_error`) ; tout échec de décodage → `[invalid_arg] chemin: motif`, in-band et audité. `Parameters<T>` n'est employé que pour les prompts (erreurs `-32602`) et comme repli si le spike rmcp échoue (V-28 ; spike reporté avant les cas d'usage de M3, §11.1), repli à acter par ADR (ADR-0008). Erreurs de protocole JSON-RPC restantes : outil inconnu (`-32602`), `arguments` qui n'est pas un objet (rejeté par rmcp avant notre code : `-32601` tant que le bug rmcp #1347 est ouvert, `-32602` après sa correction ; test documentaire, 05, 06), JSON-RPC malformé, version non supportée (`-32022`) ; ressources : §6.
- `CorpusError::InvalidRequest` (400 PISTE sans marqueur « introuvable », ou garde défensive de l'adapter) → `[upstream_error] Legifrance rejected the request (HTTP 400): {détail}` (parité S10, `warn!` « bug probable ») : `{détail}` est le message PISTE nettoyé (≤ 200 caractères, jeton et secret client retirés) pour une **consultation**, et le texte générique `HTTP 400 on /search` pour une **recherche**, dont le message PISTE n'est jamais recopié (il peut citer le texte de la requête, 04 §12.5) ; `HTTP 400 on {endpoint}` aussi quand le corps d'une consultation ne livre rien d'utilisable (04 §11.2). **Exception** : `InvalidRequest { status: Some(403), detail: "request rejected by the PISTE gateway" }` (page HTML de la passerelle, pas un refus d'accès à l'API ; V-81, 04 §11.2) s'affiche avec son statut, `(HTTP 403)`, et jamais comme `config_error`. **Exception** : `InvalidRequest { status: None }` (garde défensive locale, aucune requête partie) ne s'affiche jamais « HTTP 400 » : `lf-application::messages` (livré, plan 3a) rend un gabarit distinct, `[upstream_error] the request was not sent to Legifrance ({détail}); report it.` (cause `Decode` ; 07 T-M2-09). Toute contrainte imputable à l'entrée (dates, fond sans facette, pagination profonde, formats) est validée avant l'appel du port et rendue `invalid_arg` ; l'adapter n'en garde qu'une copie défensive. `Auth` couvre les identifiants refusés (`AuthOrigin::Token` : OAuth 400, 401 ou 403 ; `AuthOrigin::Api` : second 401 de l'API) et le 403 de l'API (`AuthOrigin::Api` de statut 403 : message « check that the PISTE application is subscribed to the Legifrance API », V-65) → `config_error`. `Timeout`, `Decode`, `TooLarge` et délai global → `upstream_error`, la cause (`UpstreamCause`) étant détaillée dans les journaux et l'audit ; l'annulation est un `AppError::Upstream` de cause `Cancelled`, sans code (§7, cas limites de l'audit). `TooLarge` (AM-45) rend sur `fr_get_act` `[upstream_error] this text is too large for fr_get_act; read its articles with fr_get_text, or find them with fr_search fond=CODE.` (C2, 04 §7.3 ; le message ne nomme que des outils exposés, `ToolName::ALL`), et sur tout autre outil le message de `Decode`, `unexpected response from Legifrance; report it.` (cause `Decode` dans les deux cas). Les opérations non couvertes hors ligne (DILA, M9) seront tranchées en M9.
- `detail` des `CorpusError` (livré, plan 3a ; AM-44) : jamais recopié dans un message du modèle, sauf celui d'`InvalidRequest` (coupé à 200 caractères) et celui de `Config { kind: Settings }` (coupé à 500 caractères), que l'adapter nettoie et expurge (jeton et secret client retirés) avant de les rendre. Tous sont journalisés pour l'opérateur par `failure::port_failure`, point d'entrée des cas d'usage pour une `CorpusError` : événement `corpus call failed` (outil, variante, `detail`, ou `what` pour `NotFound` ; `info` pour `NotFound`, `warn` sinon ; jamais l'identifiant demandé), puis délégation du message à `messages::corpus_error`, pur, qui n'appelle jamais le `Display` d'une `CorpusError`. `LF_PISTE_ENV` invalide (`ConfigKind::Settings`, problème construit par `ConfigProblem::invalid_env`) : la valeur n'est citée (`LF_PISTE_ENV='prod' is invalid: expected sandbox or production.`) que si elle fait 1 à 16 lettres ASCII ; sinon le message n'en donne que le nombre de caractères (`LF_PISTE_ENV is invalid (value not shown, {n} characters): expected sandbox or production.`) et la valeur brute n'est jamais conservée. Dérogation à la citation qu'imposait 05 §7.2, tranchée en 3a pour qu'un secret collé là par erreur n'atteigne ni le modèle ni l'audit (05 §7.2 amendé, 09 §3.16.3 ; AM-46).
- Messages `not_found` : ceux de la référence (P-013), sauf `fr_get_decision`, dont le fond suit le préfixe : `No JURI decision found for {id}.` (JURITEXT), `No CONSTIT decision found for {id}.` (CONSTEXT), `No CETAT decision found for {id}.` (CETATEXT), suivis de `Check the id, or search with fr_search.` Divergence E-15 listée dans l'annexe A.

## 7. Outils (contrat de référence ; `05-outils-mcp.md` en donne les schémas complets)
Paramètres communs aux consultations à texte long (`fr_get_decision`, `fr_get_deliberation`, `fr_get_text`) :

## 10. Qualité : tests unitaires, couverture, mutation (EXIGENCE UTILISATEUR ; `06-qualite.md` détaille)

> **Priorité.** Cette exigence (§9 Qualité du brouillon livré le 2026-10-15, recopié ci-dessous tel quel, complété de la mesure de clôture ; [ADR-0002](../adr/0002-portes-qualite.md)) l'emporte sur tout autre document du plan, `06-qualite.md`, ADR et annexes compris. Un document qui rend la couverture indicative, admet un seuil plus bas, omet la mutation ou ne la rend pas bloquante est en défaut et s'aligne sur ce paragraphe.

- Principe : **tests unitaires au maximum, mutation testing au maximum, couverture au maximum**. Les seuils ci-dessous bloquent, en local (`make ci`, `make mutants`) comme en CI. Ils ne baissent jamais ; un nouveau crate entre directement à ces seuils.
- TDD strict : test rouge, code minimal, test vert, refactorisation. Toute règle portée de la référence Python cite `fichier:ligne` dans le code ou le test.
- Tests unitaires dans le fichier du code testé (`#[cfg(test)] mod tests`), avec accès aux items privés. Viennent en plus :
  - des propriétés `proptest` pour chaque parseur, normaliseur et utilitaire texte : ne panique jamais, aller-retour, partition exacte ;
  - des cibles `cargo-fuzz` pour les entrées non fiables (identifiants, dates, HTML, texte) ;
  - en M2, les fixtures JSON de la référence pour le mapping DTO : les 16 fixtures sont installées (plan 2e, `crates/lf-adapter-piste/tests/fixtures/reference/`, créditées dans `NOTICE`) ; le domaine en lit déjà (`include_str!`) pour `from_html` et `LongText`, le mapping (plan 2f) et les tests de contrat (plan 2g) les exploitent ensuite.
- Couverture mesurée par `cargo llvm-cov --workspace --lib` : **100 % des lignes, des régions et des fonctions**. Le code de test compte dans la mesure, d'où trois formes interdites dans les tests (détail dans `CONTRIBUTING.md`) :
  - `assert!` avec des arguments de message non capturés ;
  - `assert!(matches!(…))` ;
  - `let … else { panic!() }`.

  Les adapters à I/O isolent leur logique en fonctions pures testées (mapping, retry, backoff, rendu). La glue irréductible (`main.rs`, appel réseau brut) tient dans des fichiers minces, exclus nommément et avec justification.
- Mutation par `cargo-mutants` : **0 mutant `MISSED`** sur les mutants viables. Un `TIMEOUT` (code de sortie 3) bloque aussi. Toute boucle doit donc garantir sa progression, même mutée : consommer au moins un élément par tour, ou borner le nombre de tours. Un mutant de `text::clean` bouclait sans fin à l'essai à blanc. Un mutant n'est exclu que s'il est prouvé équivalent, preuve en commentaire dans `.cargo/mutants.toml` (`exclude_re`).
  - En local, un fichier à la fois : `make mutants FILE=…`, soit `TMPDIR=/var/tmp NEXTEST_TEST_THREADS=2 cargo mutants -j 1 --file …` après contrôle mémoire, selon la règle WSL.
  - En CI, le diff de chaque PR est muté et bloque la PR. Le workspace entier est balayé chaque semaine en 4 shards, avec les cibles de fuzz.
- Mesure de référence : essai à blanc du plan 1 sur M0–M1, le 2026-10-15.
