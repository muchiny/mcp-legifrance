- Outils MCP : préfixe `fr_` ; on garde les 8 noms de la référence.
- Configuration : variables d'environnement seulement (aucun fichier, ADR-0005) ; liste fermée ci-dessous, toute nouvelle variable amende ce paragraphe ; formats, priorités et messages détaillés : 02 §8.2.

  - Compatibilité : lecture des `FR_ELI_CLIENT_ID`/`FR_ELI_CLIENT_SECRET`/`FR_ELI_OAUTH_URL`/`FR_ELI_BASE_URL`/`FR_ELI_AUDIT_DIR` avec avertissement de dépréciation sur stderr (`LF_*` l'emporte si les deux sont définies) ; `FR_ELI_CACHE_DIR`, `FR_ELI_RUNTIME_URL`, `FR_ELI_ENV`, `PISTE_CLIENT_ID`/`PISTE_CLIENT_SECRET` ne sont jamais lues et, si elles sont définies, produisent un avertissement « ignored » au démarrage et dans `check-config`.

  - Configuration invalide : le serveur démarre en mode dégradé (`error!`), chaque outil PISTE renvoie `[config_error] …` sans E/S, `fr_coverage` et `check-config` décrivent le problème.
- AUCUNE configuration distante : pas de manifeste téléchargé, aucune télémétrie (ADR-0005, corrige D-04 et D-05 : manifeste runtime distant et son téléchargement synchrone).

## 2. Workspace Cargo
- Édition 2024, `resolver = "3"` explicite dans le `Cargo.toml` racine (workspace virtuel), `[workspace.dependencies]`, `[workspace.lints]` (rust + clippy, dont `unsafe_code = "forbid"`), `rust-version = "1.91"` (MSRV), toolchain épinglée dans `rust-toolchain.toml` sur la stable courante (1.99.0, sortie le 2026-10-01 d'après la cadence de six semaines : **NON VÉRIFIÉ** [v:date-rust-1-99], V-16) avec `rustfmt` et `clippy` ; tant que le conteneur de développement ne peut pas l'installer, `RUSTUP_TOOLCHAIN=1.97.0` en local, la CI gardant l'épinglage (Q6). Piège : `default-features` hérité d'une dépendance de workspace n'est respecté qu'à partir de Rust 1.99 en édition 2024 → déclarer `default-features = false` au niveau du workspace quand c'est voulu.
- Âge minimal des dépendances : toute version figée dans `Cargo.lock` est publiée depuis au moins 14 jours à la date du verrouillage (pubtime de l'index sparse), sauf correctif de sécurité justifié dans la PR. Les versions citées dans le plan sont des planchers relevés le 2026-10-15 ; le verrou initial est fait à l'ouverture de M0, en prenant le correctif précédent d'une version trop récente. Exception : `rmcp`/`rmcp-macros` `=3.5.1` (14 jours le 2026-10-19 ; le spike M0 peut commencer avant). Si `schemars` 1.2.3 est trop récent, le lint `unused_qualifications` reste désactivé jusqu'à ce qu'il ait 14 jours (R-22).

## 3. Ports (`lf-application::ports`)
- Style : traits en async natif façon RPITIT, `fn get_decision(&self, id: &DecisionId) -> impl Future<Output = Result<Decision, CorpusError>> + Send;` implémentés avec `async fn` ; génériques (dispatch statique) ; sélection PISTE/DILA à l'exécution par un `enum AnyCorpus` (M9). Pas de `async_trait`/`dyn` sauf justification (ADR-0012).
- `LegalCorpus` (sortant, unique) : `search(&SearchQuery) -> SearchPage` ; `get_act(&LegiTextId, VersionDate) -> Act` ; `get_article(&ArticleId) -> ArticleText` ; `get_decision(&DecisionId) -> Decision` ; `get_deliberation(&CnilTextId) -> Deliberation` ; `get_convention(&KaliTextId) -> Convention` ; `get_company_agreement(&AccoTextId) -> CompanyAgreement`. Ajouts : M6 `find_article(&CodeRef, &ArticleNum, VersionDate)`, `find_by_number(...)` pour la résolution, `list_codes()` (codes abrogés compris, avec leur `etat` ; chargée paresseusement au premier besoin, jamais au démarrage ; l'adapter garde une seule table, TTL 7 j, qui sert aussi `find_article` et les completions de M7) ; M7 `article_versions(&ArticleId) -> Vec<ArticleVersion>`, `related_links(&ArticleId)`. Pas de méthode `suggest` (`/suggest` retiré, §8).
- `AuditLog` (sortant) : `record(&AuditRecord) -> Result<(), AuditError>`.
- `Clock` (sortant) : `now_utc()`, `today_paris() -> NaiveDate`.
- Entrant : pas de trait ; cas d'usage `…UseCase` avec `async fn execute(&self, input) -> Result<Output, AppError>`, regroupés dans `LegalService<C: LegalCorpus, A: AuditLog, K: Clock>` injecté dans l'adapter MCP. `Audited` enveloppe CHAQUE exécution : succès, `invalid_arg` (y compris les échecs de décodage des arguments, §5), `not_found`, erreurs amont — tout est journalisé avec une durée réelle (corrige D-02 et D-03).
- Délai global : `Audited` mesure la durée (`tokio::time::Instant`), exécute le cas d'usage sous `tokio::time::timeout(LF_TOOL_DEADLINE_S)` (seule garde dure) et publie l'échéance dans `lf_application::deadline::Deadline`, variable locale de tâche (`tokio::task_local!`, feature `rt` de tokio, §2). Les adapters la lisent (`Deadline::current_or(défaut)`) comme une durée restante (`Duration`), convertie dans leur propre horloge monotone à l'entrée de la méthode du port (les horloges de test des adapters restent cohérentes), et ne programment aucune tentative ni attente qui la dépasserait : ils rendent tout de suite une erreur explicite (`RateLimited { retry_after }`, `Timeout` ou dernière erreur). Les cas d'usage n'utilisent pas `tokio::spawn` (sinon, propagation explicite) ; ceux à appels multiples cessent d'en lancer à 80 % du délai et rendent un résultat partiel motivé. Dépassement → `upstream_error` (`UpstreamCause::Deadline`).

## 4. Domaine (`lf-domain`)
- IDs : newtypes `LegiTextId`, `LegiArtiId`, `JorfTextId`, `KaliTextId`, `KaliArtiId`, `JuriTextId`, `ConsTextId`, `CetaTextId`, `CnilTextId`, `AccoTextId` = préfixe de 8 lettres + 12 chiffres (vérifié sur toutes les fixtures) ; `FromStr` strict ; le suffixe de version `_JJ-MM-AAAA` (LEGITEXT seulement) est séparé en `VersionedId { id, version_start }` à la normalisation. Entrée utilisateur : suffixe admis sur `LEGITEXT` seulement (sinon `invalid_arg`) ; données amont : un suffixe sur un autre préfixe est retiré avec un diagnostic (`debug!` + compteur), sans être conservé. Enums `ArticleId { Legi, Kali }`, `DecisionId { Juri, Constit, Cetat }` : la juridiction et l'URL se déduisent du préfixe validé, jamais du champ `origine` (corrige D-28).
- `Fond` : `Loda, Code, Juri, Constit, Cetat, Cnil, Kali, Acco` (+ `Jorf` M7) ↔ fond API (`LODA_DATE`, `CODE_DATE`, `JURI`, …). La surface JORF complète (lecture d'un `JORFTEXT`, valeur `JORF` des enums `fond`/`fonds`, instructions) est tranchée à l'ouverture de M7 avec son endpoint (§8) ; d'ici là, `fond` a 8 valeurs.
- `Ecli` : newtype validé `ECLI:FR:…`, jamais fabriqué ; un ECLI d'un autre pays n'est pas un `Ecli` (le parseur le classe `ForeignEcli`, ci-dessous).
- Contrat de citation v2 (ADR-0009) : chaque entité citable expose `citation` (chaîne au format français correct) et `source_url` (URL legifrance.gouv.fr stable) ; `ecli` seulement s'il est natif ; `eli` seulement si un ELI natif est renvoyé (jamais fabriqué ; aujourd'hui toujours absent). Le champ `eli_uri` de la référence (toujours égal à `source_url`) n'est pas reproduit ; la note ELI passe dans les instructions et `fr_coverage`. Formats corrigés (divergences volontaires de la parité) : « Cons. const., décision n° 2025-1173 QPC du 7 novembre 2025 », « CNIL, délibération n° SAN-2026-002 du 8 janvier 2026 », mois accentués, « 1er » ; « Code civil, art. 9 » inchangé. Formats complémentaires (adoptés par défaut, Q12 ; décidés avant les golden de M1) : article d'un texte non codifié = « {titre officiel du texte, sans appel de note final « (n) »}, art. {num} » ; convention KALI = titre nettoyé, sans IDCC (l'IDCC est un champ) ; hits de recherche CONSTIT et CNIL = titre officiel (parité), la règle de consultation s'applique aux consultations ; Conseil constitutionnel sans l'objet entre crochets, lisible dans `title`.
- URL d'un `LEGIARTI` : `/codes/article_lc/{id}` si le texte parent est un code ; `/loda/article_lc/{id}` si c'est un texte non codifié (LOI, ORDONNANCE, DECRET, ARRETE…) ; `/codes/article_lc/{id}` si la nature du parent est inconnue (repli de parité). URL non datée en v0.1. Divergence volontaire E-19/D-29 (scénario smoke 3 transposé). Bloquant pour v0.1.0 : V-140 (forme canonique) et V-142 (`textTitles[].nature`) ; voir aussi V-141 (`/codes/article_lc/` pour un article de loi, assertion de la référence).
- Dates : `chrono::NaiveDate` ; epoch ms négatifs supportés (1804) ; toute date ≥ 2222-01-01 (sentinelles observées `2999-01-01` et `2222-02-22`, règle des champs `…Computed` de l'OpenAPI) et tout `…Computed` nul → `None`, donc champ omis en sortie. Le sens d'un champ omis est documenté par champ dans les descriptions d'outils : date de fin → « en vigueur sans date de fin » ; date de début → « date d'entrée en vigueur non déterminée » (l'`etat` `VIGUEUR_DIFF` porte l'information, V-101) ; date de publication ou du texte → « inconnue ». Formats d'entrée multiples (epoch ms entier ou chaîne, ISO `+0000`, `AAAA-MM-JJ`) parsés dans l'adapter ; « aujourd'hui » = date civile Europe/Paris.
- Entités : `SearchHit`, `SearchPage`, `Act`, `TocNode` (sections ET articles, ordonnés par `intOrdre` si présent, dédoublonnés), `ArticleText`, `Decision`, `Deliberation`, `Convention`, `CompanyAgreement`, `Coverage`, `LongText` (texte structuré en paragraphes).
- Texte :
  - `text::from_html` : paragraphes reconstruits depuis `texteHtml` quand disponible, sinon `texte` ; scanner de balises écrit à la main (aucun crate HTML, liste de dépendances fermée), tolérant (balise non refermée, `<` littéral, entités invalides), linéaire, sans récursion non bornée, fuzzé.
  - `text::encoding::repair_latin1_mojibake(&str) -> Cow<str>` : fonction pure, tout-ou-rien (règle du §8) ; appliquée au corps par l'adapter PISTE, réutilisée par le parseur M6 (`ParseOptions.repair_mojibake`).
  - `text::clean` : `<mark>`, espaces, NBSP — APRÈS réparation du mojibake — ; retire aussi les contrôles bidirectionnels U+202A–U+202E et U+2066–U+2069 (compteur de diagnostic), sur les textes issus de l'API seulement (le texte soumis à `fr_verify_citations` n'est pas nettoyé, ses spans s'y rapportent).
  - `text::passages`, `text::rank` (BM25 maison, repli accents/casse, mots vides français), `text::window` (fenêtre `offset`/`max_chars` coupée en fin de phrase/paragraphe).
  - `text::summary` : (1) sommaire officiel `OfficialSummary { analyses, titrages }`, mappé par fond dans l'adapter (JURI : `abstrats` → analyses, `resumePrincipal`/`autreResume` → titrages ; CETAT : `resumePrincipal` → analyses, `abstrats` → titrages), codes de classement retirés, doublons supprimés ; analyses, sinon titrages (V-109) ; (2) sinon dispositif (CONSTIT « LE CONSEIL CONSTITUTIONNEL DÉCIDE : » → « Jugé par » ; CETAT « D E C I D E » → « Délibéré ») ; (3) sinon début du texte (`lead`, au moins 600 caractères). Résumé ≤ min(`max_chars`, 1 200) caractères, coupé en fin de phrase. Pas d'heuristique « PAR CES MOTIFS » (Cour de cassation) en v0.1.
- Parseur de citations (M6) : `citation::parse(&str) -> Vec<Spanned<CitationRef>>` = `parse_with(&str, &ParseOptions::default())` ; `ParseOptions { strip_html: false, repair_mojibake: false, default_text: None, max_citations: 1 000 (garde-fou du domaine ; la borne de l'outil est appliquée par le cas d'usage), today: Option<NaiveDate> (fourni par l'application via `Clock`) }` ; spans en octets du texte reçu (conversion en caractères par `Span::to_chars`) ; winnow 1.0 sur `LocatingSlice`, ancres aho-corasick, vue « clé » repliée 1:1 pour garder les offsets ; grammaire et corpus : annexe B. Un ECLI d'un autre pays que FR est reconnu comme `CitationRef::Unsupported { family: ForeignEcli }` (code `ecli_etranger`), statut `unresolvable`.
- Erreurs : `DomainError` (thiserror).

## 5. Erreurs
- `CorpusError` : `NotFound`, `InvalidRequest`, `Upstream { status, retryable }` (`retryable` ne sert qu'au message, §8), `Timeout`, `RateLimited { retry_after }`, `Auth` (identifiants refusés, 403 de l'API), `Config`, `Decode`.
- `AppError` : `InvalidArgument`, `NotFound`, `Upstream` (détaillé par `UpstreamCause` : `Status(u16)`, `Network`, `Timeout`, `Deadline`, `Decode`, `Cancelled`, pour les journaux et l'audit, sans nouveau code MCP), `RateLimited`, `Config`, `Audit`.
- MCP (ADR-0010) : erreurs métier → résultat `isError: true`, texte seul `[code] message actionnable` avec codes `invalid_arg`, `not_found`, `upstream_error`, `rate_limited`, `config_error`, `audit_error` ; erreurs de protocole → JSON-RPC (liste fermée au point suivant). Une erreur OAuth (400/401/404 sur l'endpoint token) → `config_error`, jamais `not_found` (corrige D-10). Jamais de secret, de token ni d'URL avec paramètres sensibles dans un message ou un log.
- Arguments d'outil : reçus en `JsonObject` avec un `input_schema` explicite (`schema_for_input::<P>()`), décodés par `lf-adapter-mcp` (`serde_path_to_error`) ; tout échec de décodage → `[invalid_arg] chemin: motif`, in-band et audité. `Parameters<T>` n'est employé que pour les prompts (erreurs `-32602`) et comme repli si le spike M0 échoue (V-28), repli à acter par ADR (ADR-0008). Erreurs de protocole JSON-RPC restantes : outil inconnu (`-32602`), `arguments` qui n'est pas un objet, JSON-RPC malformé, version non supportée (`-32022`) ; ressources : §6.
- `CorpusError::InvalidRequest` (400 PISTE sans marqueur « introuvable », ou garde défensive de l'adapter) → `[upstream_error] Legifrance rejected the request (HTTP 400): {détail PISTE nettoyé, ≤ 200 caractères}` (parité S10, `warn!` « bug probable »). Toute contrainte imputable à l'entrée (dates, fond sans facette, pagination profonde, formats) est validée avant l'appel du port et rendue `invalid_arg` ; l'adapter n'en garde qu'une copie défensive. `Auth` couvre les identifiants refusés (OAuth 400/401, second 401 de l'API) et le 403 de l'API (message « check that the PISTE application is subscribed to the Legifrance API », V-65) → `config_error`. `Timeout`, `Decode`, délai global et annulation → `upstream_error`, la cause étant détaillée dans les journaux et l'audit. Les opérations non couvertes hors ligne (DILA, M9) seront tranchées en M9.
- Messages `not_found` : ceux de la référence (P-013), sauf `fr_get_decision`, dont le fond suit le préfixe : `No JURI decision found for {id}.` (JURITEXT), `No CONSTIT decision found for {id}.` (CONSTEXT), `No CETAT decision found for {id}.` (CETATEXT), suivis de `Check the id, or search with fr_search.` Divergence E-15 listée dans l'annexe A.

## 6. Protocole MCP (EXIGENCE UTILISATEUR : « MCP v2 »)
- Cible : révision **2026-07-28** (« modern »), serveur **dual-era** : sert aussi `2025-11-25` et `2025-06-18` (legacy, via `initialize`) car VS Code n'envoie encore que `initialize` 2025-11-25 alors que Claude Code sonde `server/discover`. `2025-03-26` non supportée (pas de `structuredContent`) — Q7.

  - Arguments d'outil en `JsonObject`, décodage audité (§5).

- Langues (adoptées par défaut, Q14) : instructions, descriptions et `title` des outils, messages d'erreur et libellés de resources en anglais ; noms et textes des prompts en français (messages insérés au nom de l'utilisateur).

## 7. Outils (contrat de référence ; `05-outils-mcp.md` en donne les schémas complets)
Paramètres communs aux consultations à texte long (`fr_get_decision`, `fr_get_deliberation`, `fr_get_text`) :
`detail: "summary" | "full"` (défaut `"summary"`, mais `"full"` quand `offset > 0` est fourni sans `detail` ; `detail = "summary"` explicite avec `offset > 0` → `invalid_arg`), `offset: u32` (défaut 0, en caractères Unicode), `max_chars: u32` (défaut 4 000, min 500, max 40 000 — sous le seuil de 50 000 caractères de Claude Code), `focus: string` optionnel (si présent : `passages` BM25 au lieu de la fenêtre), `passages: u8` (défaut 3, max 10). Sortie : métadonnées + `citation` + `source_url` + selon le mode : `summary` + `summary_source` (`official`, `dispositif`, `lead` ; §4), `text` (fenêtre) avec `text_length` et `next_offset` (absent en fin de texte), ou `passages: [{offset, text, score}]`. `max_chars` borne tout texte rendu : en mode résumé, un texte de longueur ≤ min(`max_chars`, 1 200) caractères est rendu entier dans `text` (avec le sommaire officiel s'il existe), un texte plus long donne `summary`.

Ordre de dégradation : (1) TOC : moins d'entrées, `next_toc_offset` ajusté ; (2) recherches : retrait des `snippet` en partant du dernier hit, jamais d'un hit, avec `note` ; (3) listes de `fr_verify_citations` et `fr_get_related` tronquées avec `truncated: true`. ## 8. Adapter PISTE (`lf-adapter-piste`)
- OAuth : `POST` form `grant_type=client_credentials`, `client_id`, `client_secret`, `scope=openid` ; jeton en mémoire (`secrecy::SecretString`), renouvelé 60 s avant expiration, rafraîchissement mono-vol (un seul appel concurrent), un 401 API → un seul renouvellement puis échec `Auth` (corrige D-12 : le 401 qui force un nouveau jeton à chaque tentative). URLs : sandbox `https://sandbox-oauth.piste.gouv.fr/api/oauth/token` + `https://sandbox-api.piste.gouv.fr/dila/legifrance/lf-engine-app` ; production `https://oauth.piste.gouv.fr/api/oauth/token` + `https://api.piste.gouv.fr/dila/legifrance/lf-engine-app`.
- HTTP : un seul `reqwest::Client` partagé (pool), `reqwest` 0.13, `default-features = false`, features `json`, `form`, `gzip`, `system-proxy` et TLS rustls (`rustls`, ou `rustls-no-provider` + `rustls` avec `ring` selon le spike M0 : R-09, V-02) ; ni `charset` (décodage UTF-8 strict depuis les octets, avant la réparation du mojibake), ni `http2` ; corps lus en flux et bornés à 16 Mio après décompression (au-delà : `Decode`) ; timeouts connexion 10 s / requête 40 s (`LF_HTTP_TIMEOUT_S`), User-Agent `mcp-legifrance/<version> (+https://github.com/muchiny/mcp-ligitfrance)` (dépôt : Q1) ; secrets en `secrecy::SecretString` (feature `serde` : le jeton est désérialisé directement).
- Retries : `backon` ; 3 tentatives au plus sur 429, 502, 503, 504 et erreurs réseau ; 2 tentatives au plus sur 500, puis `Upstream { status: 500, retryable: false }` (un 500 répété est présumé déterministe : facette ou champ refusé, V-69 ; retour à 3 tentatives si V-69 montre des 500 transitoires fréquents) ; backoff exponentiel avec gigue (≥ 0,5 s puis ≥ 1 s, P-024), respect de `Retry-After` (≤ 30 s), plafonné par le délai global de l'outil (`LF_TOOL_DEADLINE_S`, défaut 60 s ; `Deadline`, §3). `retryable` ne sert qu'au message : seul un échec `retryable: true` (429, 502, 503, 504, réseau, timeout) invite à réessayer.
- Débit : `governor` 0.10 (feature `std` seule, horloge injectée) consulté par `check()` avant chaque tentative, réessais compris (jamais `until_ready`, dont les attentes échappent au délai global) ; sémaphore de `LF_PISTE_CONCURRENCY` requêtes en vol ; quota par défaut 5 req/s, rafale 10 (`LF_PISTE_RPS`, `LF_PISTE_BURST`) ; valeurs PISTE réelles : **NON VÉRIFIÉ** [v:quota-piste-prod] (V-62).
- DTO : structs serde minimales, `#[serde(default)]` partout, helpers `null_default`, `opt_nonempty`, `opt_raw_date`, `opt_string_or_number` ; renommages explicites (piège `titresTM`) ; champs inconnus ignorés ; `serde_path_to_error` pour des erreurs `Decode` lisibles.
- Mojibake : l'adapter applique au corps entier, après le décodage UTF-8 strict et avant serde, la fonction pure du domaine `text::encoding::repair_latin1_mojibake` (si aucun caractère > U+00FF et motif `[U+00C2–U+00F4][U+0080–U+00BF]` ou C1 → octets latin-1 → UTF-8 strict, accepté seulement s'il ne reste aucun motif), AVANT toute normalisation des NBSP ; active par défaut, désactivable par `LF_PISTE_MOJIBAKE_REPAIR=off`, compteur + `warn` ; jamais appliquée par défaut au texte soumis par l'utilisateur (`fr_verify_citations`) ; origine à confirmer en live (V-72 ; voir aussi V-71, échappements `\uXXXX`, et V-73, forme CP1252). Stratégies contrôlées sur les fixtures par `docs/plan/annexes/donnees/scripts/dto_repair_check.py` (§10).
- Requêtes `/search` : `typeChamp` `ALL`, `typeRecherche` selon `match` (`UN_DES_MOTS`/`TOUS_LES_MOTS_DANS_UN_CHAMP`/`EXACTE`), `operateur` `ET`, `sort` `PERTINENCE`, `pageNumber`/`pageSize`, `typePagination` = valeur du `PaginationMemo` (§7) ; `DATE_VERSION` `singleDate` = midi Europe/Paris du jour `version_date`, en epoch ms (stable sur la journée ; correct que PISTE compare l'instant à des bornes stockées à minuit UTC ou le tronque en date UTC ou Paris ; confirmé par V-76 en M2) pour LODA_DATE/CODE_DATE.
