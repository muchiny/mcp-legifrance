L'horloge système (`SystemClock: Clock`, UTC + Europe/Paris via `chrono-tz`) est un module `clock` de `lf-app` : pas de crate dédié. `chrono` (`std`) sert hors du domaine (`lf-application`, adapters) ; la feature `clock` et `chrono-tz` ne servent que dans `lf-app::clock` (date du jour à Paris) et `lf-adapter-piste` (« minuit Paris » de `singleDate`), qui convertissent depuis et vers `CivilDate` (décision C3, ADR-0011).

Règles de dépendance, vérifiées en CI par `cargo xtask check-arch` (`make arch`, `xtask/src/arch.rs`) : `lf-domain` n'a pour dépendance normale que `thiserror` (liste blanche, plus stricte qu'une liste noire : ni crate `lf-*`, ni tokio/reqwest/serde_json/rmcp/chrono) ; `lf-application` ne dépend d'aucun adapter ni de `lf-app` ; aucun adapter ne dépend d'un autre adapter ni de `lf-app` ; seul `lf-app` dépend de tout. Seules les dépendances normales comptent. La porte échoue fermé : un `cargo metadata` sans membre, sans nom, sans `dependencies` ou sans `lf-domain` est une erreur, pas un succès à vide (`arch.rs:8-12`). Extensions ajoutées au jalon où elles servent (§11.1) : membre inconnu = violation (tête de M2) ; R2 (`lf-application` sans rmcp/reqwest), fermeture transitive (`cargo metadata --format-version 1 --all-features --locked`) et R9 (doublons) en M2, à la création de `lf-application` ; features de tokio bornées en M3 ; épinglage de rmcp en M4.

## 3. Ports (`lf-application::ports`)
- Style : traits en async natif façon RPITIT, `fn get_decision(&self, id: &DecisionId) -> impl Future<Output = Result<Decision, CorpusError>> + Send;` implémentés avec `async fn` ; génériques (dispatch statique) ; sélection PISTE/DILA à l'exécution par un `enum AnyCorpus` (M9). Pas de `async_trait`/`dyn` sauf justification (ADR-0012).
- `LegalCorpus` (sortant, unique) : `search(&SearchQuery) -> SearchPage` ; `get_act(&LegiTextId, VersionDate) -> Act` ; `get_article(&ArticleId) -> ArticleText` ; `get_decision(&DecisionId) -> Decision` ; `get_deliberation(&CnilTextId) -> Deliberation` ; `get_convention(&KaliTextId) -> Convention` ; `get_company_agreement(&AccoTextId) -> CompanyAgreement`. Ajouts : M6 `find_article(&CodeRef, &ArticleNum, VersionDate)`, `find_by_number(...)` pour la résolution ; M7 `article_versions(&ArticleId) -> Vec<ArticleVersion>`, `related_links(&ArticleId)`, `list_codes()`.
- `AuditLog` (sortant) : `record(&AuditRecord) -> Result<(), AuditError>`.
- `Clock` (sortant) : `now_utc()`, `today_paris() -> CivilDate` (date civile Europe/Paris, calculée par `chrono-tz` dans `lf-app::clock` ; décision C3).
- Entrant : pas de trait ; cas d'usage `…UseCase` avec `async fn execute(&self, input) -> Result<Output, AppError>`, regroupés dans `LegalService<C: LegalCorpus, A: AuditLog, K: Clock>` injecté dans l'adapter MCP. `Audited` enveloppe CHAQUE exécution : succès, `invalid_arg`, `not_found`, erreurs amont — tout est journalisé avec une durée réelle (corrige D-02 et D-03).

## 4. Domaine (`lf-domain`)
- IDs : `LegiTextId`, `LegiArtiId`, `JorfTextId`, `KaliTextId`, `KaliArtiId`, `JuriTextId`, `ConsTextId`, `CetaTextId`, `CnilTextId`, `AccoTextId` = préfixe de 8 lettres + 12 chiffres (vérifié sur toutes les fixtures). Représentation livrée : `Id<K>(String)` avec un marqueur `IdKind` (alias `LegiTextId = Id<LegiText>`…, `id.rs:42-178`), sans macro ni `Copy` ; `Id::parse` et `FromStr` tolérants (espaces autour, casse ; `id.rs:19-39`) ; propriété testée : parse∘Display = identité. Suffixe de version `_JJ-MM-AAAA` (tâche de tête de M2, décision C4) : `parse_versioned` vérifie qu'il est une vraie date et la conserve dans `VersionedId { id, version_start }` (date par défaut de `fr_get_act`, `version_start` des hits) ; un suffixe mal formé (`_foo`, `_` seul, `_31-02-2023`) est refusé (`BadSuffix`) ; un suffixe bien formé sur un autre préfixe que LEGITEXT est toléré puis retiré (tolérance documentée). Le livré retire aujourd'hui tout suffixe sans contrôle. Enums `ArticleId { Legi, Kali }`, `DecisionId { Juri, Constit, Cetat }` : la juridiction et l'URL se déduisent du préfixe validé, jamais du champ `origine` (corrige D-28).
- `Fond` : `Loda, Code, Juri, Constit, Cetat, Cnil, Kali, Acco` (+ `Jorf` M7) ↔ fond API (`LODA_DATE`, `CODE_DATE`, `JURI`, …).
- `Ecli` : newtype validé `ECLI:FR:…`, jamais fabriqué.
- Contrat de citation v2 (ADR-0009 ; décidé le 2026-10-16, décision C2 ; à implémenter en tâche de tête de M2 : le livré M1 expose encore le contrat v1 `CitationContract { eli_uri, human_readable_citation, source_url }`, `citation.rs:15-23`) : chaque entité citable expose `citation` (chaîne au format français correct, jamais vide : repli « Légifrance {ID} », une ligne, 1 000 caractères au plus) et `source_url` (URL legifrance.gouv.fr stable) ; `ecli` seulement s'il est natif ; `eli` seulement si un ELI natif est renvoyé (jamais fabriqué ; aujourd'hui toujours absent) ; newtypes `CitationText`, `SourceUrl`, `Eli`. Le champ `eli_uri` de la référence (toujours égal à `source_url`) n'est pas reproduit ; la note ELI passe dans les instructions et `fr_coverage`. Le module `citation` est renommé `contract` (`Citable::citation()` devient `contract()`), ce qui libère `citation` pour le parseur M6. Formats corrigés (divergences volontaires de la parité) : « Cons. const., décision n° 2025-1173 QPC du 7 novembre 2025 » (sans le suffixe « - objet » du livré : l'objet reste lisible dans `title`), « CNIL, délibération n° SAN-2026-002 du 8 janvier 2026 » (variante « décision » NON VÉRIFIÉ [v:cnil-nature-decision-format]), mois accentués, « 1er » ; « Code civil, art. 9 » inchangé. Cette typographie est livrée depuis M1 (Q11) : la référence écrit `decision`, `deliberation`, `fevrier` et `1 janvier` (`citations.py:283-318`, `376-378`), alors que Légifrance accentue ses propres titres (fixture `consult_cnil.json` : « Délibération SAN-2026-002 du 8 janvier 2026 »).
- Dates : `CivilDate` maison, pas `chrono` (décision C3, ADR-0011 amendé) : `crates/lf-domain/src/date.rs` (`CivilDate::new`, `parse` `AAAA-MM-JJ`, `from_unix_millis`, `to_french`, `year`/`month`/`day` ; années 1 à 9999) ; epoch ms négatifs supportés (`div_euclid` ; vecteur 1804-03-21 = `-5231606400000` à tester en tête de M2) ; sentinelles `2999-01-01` et `2222-02-22` (et `*Computed` nuls) → `None` (« sans date de fin ») par `open_ended` (seuil `SENTINEL_FLOOR` = 2222-01-01, tête de M2 ; le livré garde aujourd'hui la sentinelle comme date, `entity/act.rs:41`) ; `VersionDate`, alias de `CivilDate` dans le livré (`date.rs:39`), devient en tête de M2 un newtype borné `1500-01-01..=2221-12-31` (bornes NON VÉRIFIÉ), avec `DateRange` (`InvertedDateRange`) ; formats d'entrée multiples (epoch ms entier ou chaîne, ISO `+0000`, `AAAA-MM-JJ`) parsés dans l'adapter ; « aujourd'hui » = date civile Europe/Paris (`Clock::today_paris()`, §3).
- Entités : `SearchHit`, `SearchPage`, `Act`, table des matières, `ArticleText`, `Decision`, `Deliberation`, `Convention`, `CompanyAgreement`, `Coverage`, `LongText` (texte structuré en paragraphes, M2). Table des matières : le `TocEntry` livré (liste plate d'articles, `entity/act.rs:13`) est renommé `TocArticle`, puis l'arbre `TocNode` (sections ET articles, `Toc::build`, `Toc::page`, ordonnés par `intOrdre` si tous les frères l'ont, dédoublonnés, profondeur ≤ 64, `DomainError::TocTooDeep`) arrive en tête de M2 (décision C4).
- Texte : `text::clean` = HTML vers texte (livré, `text/clean.rs:15` : balises retirées dont `<mark>`, `<br>`/`<p>` → sauts de ligne et paragraphes, entités décodées, espaces, NBSP — APRÈS réparation du mojibake) ; `text::encoding::repair_latin1_mojibake` et `has_latin1_mojibake` (fonction pure tout-ou-rien appelée par l'adapter au niveau du corps, §8 ; reliquat de M1, tâche de tête de M2) ; `text::from_html` (M2 : seulement la structure en paragraphes, depuis `texteHtml` quand disponible, sinon `texte`) ; `text::passages` ; `text::rank` (BM25 maison, repli accents/casse ; mots vides français et repli NFD en M5) ; `text::window` (livré : `window(&str, offset, max_chars) -> Window { text, next_offset }`, fonction totale, fenêtre `offset`/`max_chars` coupée en fin de phrase/paragraphe ; tient lieu de `text::truncate`) ; `text::summary` (M5 : résumé officiel `sommaire`, sinon extraction du dispositif : CONSTIT « LE CONSEIL CONSTITUTIONNEL DÉCIDE : » → « Jugé par », CETAT « D E C I D E » → « Délibéré »).
- Parseur de citations (M6) : `citation::parse(&str) -> Vec<Spanned<CitationRef>>` (winnow 1.0 sur `LocatingSlice`, ancres aho-corasick, vue « clé » repliée 1:1 pour garder les offsets) ; grammaire et corpus : annexe B.
- Erreurs : `DomainError` (thiserror).

## 5. Erreurs
- `CorpusError` : `NotFound`, `InvalidRequest`, `Upstream { status, retryable }`, `Timeout`, `RateLimited { retry_after }`, `Auth` (identifiants refusés), `Config`, `Decode`.
- `AppError` : `InvalidArgument`, `NotFound`, `Upstream`, `RateLimited`, `Config`, `Audit`.
- MCP (ADR-0010) : erreurs métier → résultat `isError: true`, texte seul `[code] message actionnable` avec codes `invalid_arg`, `not_found`, `upstream_error`, `rate_limited`, `config_error`, `audit_error` ; erreurs de protocole (outil inconnu, params non désérialisables quand rmcp les traite ainsi) → JSON-RPC. Une erreur OAuth (400/401/404 sur l'endpoint token) → `config_error`, jamais `not_found` (corrige D-10). Jamais de secret, de token ni d'URL avec paramètres sensibles dans un message ou un log.

## 6. Protocole MCP (EXIGENCE UTILISATEUR : « MCP v2 »)
- Cible : révision **2026-07-28** (« modern »), serveur **dual-era** : sert aussi `2025-11-25` et `2025-06-18` (legacy, via `initialize`, jamais au détriment de la conformité 2026-07-28) car VS Code n'envoie encore que `initialize` 2025-11-25 alors que Claude Code sonde `server/discover`. `2025-03-26` non supportée (pas de `structuredContent`) — Q7.
- SDK : `rmcp` + `rmcp-macros` épinglés `=3.5.1` (MSRV 1.88, édition 2024), features par défaut + `transport-io` ; `transport-streamable-http-server` seulement en M8. Montées de version : manuelles, testées (l'API a changé de majeure 4 fois en 2026 ; `LATEST` a changé dans une mineure). Le protocole reste confiné à `lf-adapter-mcp`.
- `supported_protocol_versions()` explicite : `[2026-07-28, 2025-11-25, 2025-06-18]`. `get_info()` renvoie `ServerConfig` avec `Implementation::new("mcp-legifrance", env!("CARGO_PKG_VERSION"))` explicite (jamais `from_build_env`).
- Règles : `server/discover` servi depuis des données statiques ; démarrage SANS appel réseau (OAuth paresseux au premier appel d'outil) ; ne jamais quitter sur une méthode inattendue ; `ttlMs`/`cacheScope` explicites (proposition Q8 : listes `ttlMs = 3 600 000`, `cacheScope = public` ; `resources/read` `ttlMs = 3 600 000`, `public`) ; `resultType` géré par rmcp ; ressource inconnue → `-32602` ; codes de la spec `-32020` (en-têtes incohérents avec le corps), `-32021` (capacité client manquante), `-32022` (version non supportée), jamais de code maison dans la plage réservée ; pas de capacité `logging` (dépréciée ; `logging/setLevel` et `ping` supprimés) → journaux `tracing` sur stderr seulement, jamais au niveau debug de rmcp en production (il journalise les réponses complètes) ; ni sampling, ni roots, ni elicitation, ni MRTR ; pas de `x-mcp-header` ni d'en-têtes `Mcp-Param-*` (bug rmcp #1348) ; `outputSchema`/`structuredContent` toujours à racine objet (bug rmcp #1337) ; pas de combinateur racine ni de `$ref` externe ; propriétés de premier niveau ≤ 64 caractères ; noms d'outils `^[a-zA-Z0-9_-]{1,64}$`.
- Instructions serveur : en anglais, ≤ 3 500 caractères (Claude Code coupe à 4 096 ; la référence fait 4 470), testées par un test de dérive (outils et codes d'erreur cités = outils et codes réels) et un test de taille.
- Descriptions d'outils : anglais, 3 à 6 phrases, disent quand utiliser l'outil, les valeurs par défaut et comment obtenir la suite ; verrouillées par le descriptor lock.
- Sortie (ADR-0006) : sur succès, Claude Code et VS Code transmettent au modèle `structuredContent` (pas le texte) → le `structuredContent` EST la réponse compacte : champs `None` omis (`skip_serializing_if`), pas de doublons, pas de métadonnées inutiles ; le `TextContent` de repli contient la sérialisation JSON du même objet (lettre de la spec) ; sur erreur, texte seul. Annotations : `read_only_hint = true`, `destructive_hint = false`, `idempotent_hint = true`, `open_world_hint = true` (service externe ; parité).
- HTTP (M8, optionnel) : Streamable HTTP sans session (POST seul ; GET/DELETE → 405), validation `Origin` (403), écoute sur `127.0.0.1` par défaut, `allowed_hosts`, en-têtes `MCP-Protocol-Version`/`Mcp-Method`/`Mcp-Name` validés par rmcp ; deux profils : local (jeton statique) puis distant (resource server OAuth : PRM RFC 9728, audience RFC 8707, 401/403 `insufficient_scope`, jamais de token passthrough vers PISTE). Conditionné aux CGU (Q4).

## 10. Qualité : tests unitaires, couverture, mutation (EXIGENCE UTILISATEUR ; `06-qualite.md` détaille)

> **Priorité.** Cette exigence (§9 Qualité du brouillon livré le 2026-10-15, recopié ci-dessous tel quel, complété de la mesure de clôture ; [ADR-0002](../adr/0002-portes-qualite.md)) l'emporte sur tout autre document du plan, `06-qualite.md`, ADR et annexes compris. Un document qui rend la couverture indicative, admet un seuil plus bas, omet la mutation ou ne la rend pas bloquante est en défaut et s'aligne sur ce paragraphe.

- Principe : **tests unitaires au maximum, mutation testing au maximum, couverture au maximum**. Les seuils ci-dessous bloquent, en local (`make ci`, `make mutants`) comme en CI. Ils ne baissent jamais ; un nouveau crate entre directement à ces seuils.
- TDD strict : test rouge, code minimal, test vert, refactorisation. Toute règle portée de la référence Python cite `fichier:ligne` dans le code ou le test.
- Tests unitaires dans le fichier du code testé (`#[cfg(test)] mod tests`), avec accès aux items privés. Viennent en plus :
  - des propriétés `proptest` pour chaque parseur, normaliseur et utilitaire texte : ne panique jamais, aller-retour, partition exacte ;
  - des cibles `cargo-fuzz` pour les entrées non fiables (identifiants, dates, HTML, texte) ;
  - en M2, les fixtures JSON de la référence pour le mapping DTO.
- Couverture mesurée par `cargo llvm-cov --workspace --lib` : **100 % des lignes, des régions et des fonctions**. Le code de test compte dans la mesure, d'où trois formes interdites dans les tests (détail dans `CONTRIBUTING.md`) :
  - `assert!` avec des arguments de message non capturés ;
  - `assert!(matches!(…))` ;
  - `let … else { panic!() }`.

  Les adapters à I/O isolent leur logique en fonctions pures testées (mapping, retry, backoff, rendu). La glue irréductible (`main.rs`, appel réseau brut) tient dans des fichiers minces, exclus nommément et avec justification.
- Mutation par `cargo-mutants` : **0 mutant `MISSED`** sur les mutants viables. Un `TIMEOUT` (code de sortie 3) bloque aussi. Toute boucle doit donc garantir sa progression, même mutée : consommer au moins un élément par tour, ou borner le nombre de tours. Un mutant de `text::clean` bouclait sans fin à l'essai à blanc. Un mutant n'est exclu que s'il est prouvé équivalent, preuve en commentaire dans `.cargo/mutants.toml` (`exclude_re`).
  - En local, un fichier à la fois : `make mutants FILE=…`, soit `TMPDIR=/var/tmp NEXTEST_TEST_THREADS=2 cargo mutants -j 1 --file …` après contrôle mémoire, selon la règle WSL.
  - En CI, le diff de chaque PR est muté et bloque la PR. Le workspace entier est balayé chaque semaine en 4 shards, avec les cibles de fuzz.
- Mesure de référence : essai à blanc du plan 1 sur M0–M1, le 2026-10-15. Le relevé (nombre de tests, couverture lignes/régions/fonctions, mutants testés et survivants) figure dans l'en-tête du plan 1. Mesure de clôture de M0–M1 (ADR-0002) : 137 tests (129 `lf-domain`, 8 `xtask`) ; 100 % des lignes, régions et fonctions ; 369 mutants, 0 `MISSED`, 0 `TIMEOUT` (334 tués, 35 non compilables), sans aucun `exclude_re`.
- Outils écartés : `typos`, faux positifs sur le français (30 mots distincts relevés sur l'essai à blanc).
- Fin de jalon : agents `quality-checker`, `test-amplifier`, `security-auditor` puis `code-reviewer`, dans l'ordre de `~/.claude/rules/agent-coordination.md`.

Tests prévus par le plan et CI :
- Tests : unitaires domaine (+ `proptest` pour IDs, dates, fenêtrage), table-driven du parseur sur le corpus de l'annexe B, tests golden de parité depuis `docs/plan/annexes/donnees/parite-golden.json` (divergences volontaires listées), tests d'adapter `wiremock` + fixtures de la référence (avec attribution), tests MCP in-process (`tokio::io::duplex`) + snapshots `insta`, descriptor lock (`tests/tools.lock.json` régénéré par `cargo xtask lock-descriptors`), test de dérive et de taille des instructions, tests JSON-RPC bruts en stdio pour les deux ères (discover moderne + initialize legacy), suite de conformité officielle sur le transport HTTP (M8), smoke tests live opt-in (`--ignored`, identifiants requis). Pour compter dans `--lib`, mapping DTO, classement HTTP vers `CorpusError`, retry, scénarios `wiremock` async, `Audited` sur doubles, corpus de citations et golden de niveau 1 (`include_str!`) sont des tests unitaires du crate ; `tests/` est réservé à `live.rs` (`#[ignore]`), aux tests e2e du binaire (golden de niveau 2) et aux compléments.
- CI GitHub Actions (livrée ; elle appelle les cibles du `Makefile`, et `make ci` = `fmt-check lint test doc arch deny machete cov`, `Makefile:62`) :
  - `ci.yml`, à chaque PR et sur `main` : `check` (`make fmt-check lint doc arch machete` : `fmt --check`, `clippy --workspace --all-targets -D warnings`, rustdoc `-D warnings`, `check-arch`, `cargo machete`) ; `test` (`make test` : `cargo nextest run --workspace` puis doc-tests) ; `coverage` (`make cov` : `--fail-under-lines`, `--fail-under-regions` et `--fail-under-functions` à 100, `Makefile:7-8`) ; `deny` (`cargo deny check` : licences, advisories, bans, sources) ; `msrv` (MSRV 1.88 : `cargo +1.88 check --workspace --all-targets`) ; `mutants`, sur les PR : diff de la PR muté (`cargo mutants --in-diff pr.diff -j 2 --baseline skip --timeout 60`), `MISSED` (code 2) et `TIMEOUT` (code 3) bloquent la PR ; ce job est exempté du budget de durée de la CI, son coût suivant la taille du diff (`ci.yml:19-118`).
  - `weekly.yml`, chaque lundi : `cargo mutants --shard k/4 -j 2 --timeout 60` sur tout le workspace en 4 shards, et fuzz `ids` et `text` (nightly, 300 s par cible) (`weekly.yml:15-62`).

Toute nouvelle porte du plan (`cargo xtask lock-descriptors`, `instructions-size`, contrôle des fixtures) entre dans le `Makefile`, pas directement dans la CI.
- Définition de « terminé » (toute tâche, tout jalon) : `make ci` vert, `make cov` à 100 %, 0 `MISSED` et 0 `TIMEOUT` sur le diff.
